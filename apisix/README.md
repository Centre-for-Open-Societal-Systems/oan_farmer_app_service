# APISIX gateway config (ADC)

`adc.yaml` and `k8s/templates/` are generated by `generate_apisix_config.py`. Do not edit them.
Same layout and tooling as `oan_grievance_service/apisix/`; shared logic is in
`oan_auth_service/gateway_apisix.py`.

```bash
PYTHONPATH=. python3 apisix/generate_apisix_config.py   # routes + tiers -> adc.yaml, k8s/templates
adc lint -f apisix/adc.yaml
adc diff -f apisix/adc.yaml --label-selector app=oan-farmer-app
adc sync -f apisix/adc.yaml --label-selector app=oan-farmer-app
```

Routes are the ones declared with `router.mobile_route` (read back with `declared_routes("oan_farmer_app_service")`); the tier is picked by
the generator from the method and whether the route is public. `oan_auth_service`'s own
`/v1/auth/*`, `/v1/admin/*` and `/v1/notifications/*` are added with `gw.with_auth_routes`,
which refuses a (method, path) that this app also declares.

Backend routes match `/<service>/<version>/...` (`/a2c/v1/...`), with the version left to the app; auth routes match `/v1/...`. A service-level `proxy-rewrite` puts `/api` in front of any of them for Frappe (`/api/a2c/v1/...`, `/api/v1/auth/...`).

Attachment and export routes go to the grievance backend (`oan-farmer-app-files-v1`) and never
touch Frappe. The gateway does not verify tokens on them; the grievance backend does.

Environment read when the file is generated: `APISIX_REDIS_HOST`, `APISIX_REDIS_PORT`,
`CORS_ORIGINS_REGEX`. Read by ADC at sync time: `OAN_FARMER_APP_UPSTREAM_HOST`,
`OAN_GRIEVANCE_UPSTREAM_HOST`, `FRAPPE_SITE_NAME`.

`GRIEVANCE_API_PREFIX` (default `/api`) is what the attachment and export rewrites put in front of the version on the grievance host. Set it empty if that host is reached through the backend's own gateway, then re-run the generator.
